# Подробный разбор кода калькулятора

Этот документ объясняет, что делает каждый файл, как проходит вычисление и почему код разделён на модули. Исходники: [Program.cs](../Program.cs), [Form1.Designer.cs](../Form1.Designer.cs), [Form1.cs](../Form1.cs), [CalculatorSession.cs](../CalculatorSession.cs), [Calculator.cs](../Calculator.cs) и [CalculatorTests.cs](../Tests/CalculatorTests.cs).

## 1. Общая схема

```text
Program.Main
    ↓ открывает
Form1 (окно, ввод и кнопки)
    ↓ передаёт строки
CalculatorSession (проверка и преобразование ввода)
    ↓ передаёт decimal
Calculator (четыре арифметические операции)
    ↓ возвращает число или исключение
CalculatorSession (текст результата или ошибки)
    ↓
Form1 (вывод на экран)
```

Такое разделение нужно для тестирования. Арифметику можно проверить без запуска окна. Обработку строк можно проверить без нажатия кнопок. Окно можно проверить отдельно, задавая значения его полям.

## 2. Как запускается приложение

`SoftwareTesting.csproj` задаёт `net8.0-windows` и `UseWindowsForms=true`: проект рассчитан на Windows и может использовать классы `Form`, `TextBox`, `Button`. `OutputType=WinExe` означает оконное приложение, поэтому при обычном запуске не появляется отдельная консоль. Запись `Compile Remove="Tests\**\*.cs"` исключает исходники тестов из основного проекта: иначе стандартное правило .NET включило бы все `.cs` из вложенной папки `Tests` и попыталось скомпилировать тесты вместе с приложением.

В `Program.Main` атрибут `[STAThread]` задаёт режим потока, необходимый для корректной работы Windows Forms. `ApplicationConfiguration.Initialize()` применяет стандартные настройки приложения, а `Application.Run(new Form1())` создаёт окно и запускает обработку событий. Программа работает, пока окно не будет закрыто.

## 3. Что находится в форме

Класс `Form1` разделён ключевым словом `partial` на два файла:

- `Form1.Designer.cs` создаёт и настраивает элементы интерфейса.
- `Form1.cs` содержит реакцию на действия пользователя.

Это один класс, разделённый по назначению. В конструкторе `Form1()` вызывается `InitializeComponent()`: создаются два поля для чисел, список операций, поле результата, подписи и кнопки. `ComboBoxStyle.DropDownList` не позволяет ввести произвольную операцию в список. В списке находятся `+`, `-`, `×`, `÷`, а `SelectedIndex = 0` делает сложение начальным выбором.

У `resultTextBox` стоит `ReadOnly = true`, чтобы результат меняла программа, а не пользователь. `AcceptButton = calculateButton` привязывает Enter к кнопке «Вычислить». Свойство `Name` у элементов помогает тестам найти нужное поле или кнопку через `Controls.Find`.

В дизайнере также привязаны события:

```csharp
calculateButton.Click += CalculateButton_Click;
clearButton.Click += ClearButton_Click;
firstNumberTextBox.TextChanged += InputChanged;
secondNumberTextBox.TextChanged += InputChanged;
operationComboBox.SelectedIndexChanged += InputChanged;
```

Знак `+=` добавляет метод-обработчик к событию. Когда меняется число или операция, `InputChanged` удаляет старый результат и старую ошибку. Это важно: ответ `5`, полученный для `2 + 3`, не должен оставаться на экране после замены `2` на `10`. Новое вычисление при редактировании **не запускается** — пользователь снова нажимает «Вычислить».

## 4. Нажатие «Вычислить» и «Очистить»

`CalculateButton_Click` читает текст двух полей и выбранную операцию. Он вызывает `CalculatorSession.TryCalculate(...)`. Метод возвращает `true`, если удалось получить число, и `false`, если возникла ошибка. Дополнительно через параметры `out` он возвращает строку результата и строку ошибки.

При `true` форма записывает `result` в поле результата и очищает подпись ошибки. При `false` она очищает поле результата и показывает `error`. Очистка прежнего результата не даёт принять старое число за ответ на новый, ошибочный ввод.

`ClearButton_Click` очищает оба операнда, результат и ошибку, возвращает выбор на `+` и переводит фокус в первое поле. Это возвращает форму в начальное состояние для следующего расчёта.

## 5. Зачем нужен CalculatorSession

Форма работает со строками, а арифметический модуль — с числами типа `decimal`. `CalculatorSession` служит промежуточным слоем между ними. Его метод имеет вид:

```csharp
bool TryCalculate(string firstText, string secondText, string operation,
    out string result, out string error)
```

В начале `result` и `error` становятся пустыми. Метод вызывает `TryReadNumber` для каждого операнда. В условии используется `||`: если первое число не удалось прочитать, второй вызов уже не нужен. При неверном вводе метод возвращает `false` и сообщение «Введите два числа.»; `Calculator` в таком случае вообще не вызывается.

После успешного преобразования строк вызывается `Calculator.Calculate`. Результат переводится обратно в строку через `ToString("G29", CultureInfo.CurrentCulture)`. Формат `G29` выводит число без ненужных конечных нулей: `1,5 × 2` показывается как `3`, а не `3,0`. `CurrentCulture` даёт привычную пользователю десятичную запятую при русских настройках.

`try/catch` переводит ошибки вычисления в сообщения интерфейса:

| Исключение | Причина | Сообщение пользователю |
| --- | --- | --- |
| `DivideByZeroException` | Второй операнд деления равен нулю | «На ноль делить нельзя.» |
| `OverflowException` | Результат не помещается в `decimal` | «Результат слишком велик.» |
| `ArgumentException` | Модулю передана неподдерживаемая операция | «Выберите операцию.» |

Исключения остаются полезными внутри вычислительного модуля, а интерфейс получает понятные строки. Возврат `bool` позволяет форме обработать оба случая без собственного `try/catch`.

## 6. Как разбираются числа

`TryReadNumber` сначала вызывает `Trim()`, поэтому пробелы вокруг значения не мешают. Далее есть две ветви.

**Один тип разделителя.** Для `1,5` или `1.5` точка и запятая приводятся к десятичному разделителю текущей культуры, затем `decimal.TryParse` пытается получить число. `TryParse` возвращает `false` при неверной строке вместо исключения.

**И точка, и запятая.** Для `1,234.5` либо `1.234,5` последний из двух разных символов считается десятичным разделителем, а другой — разделителем групп разрядов. Регулярное выражение сначала проверяет форму записи. Например, для `1,234.5` шаблон требует начальную группу из 1–3 цифр, затем одну или несколько групп **строго по три цифры** после запятой и дробную часть после точки. Поэтому запись `12,34.5` не принимается. После проверки разделители групп удаляются, десятичным разделителем становится точка, а `decimal.TryParse` вызывается с `InvariantCulture`. В обеих допустимых формах получается число `1234.5m`.

Это соглашение для удобства ввода, а не универсальный разбор чисел всех стран. Когда в строке только один разделитель, он трактуется как десятичный; запись `1,234` означает `1,234`, а не `1234`.

## 7. Как работает Calculator

`Calculator.Calculate(decimal firstNumber, decimal secondNumber, string operation)` получает уже проверенные числа. Выражение `switch` выбирает действие по строке операции:

- `+`: сложение;
- `-`: вычитание, где порядок операндов важен;
- `×` и `*`: умножение;
- `÷` и `/`: деление.

В форме показываются символы `×` и `÷`, но модуль понимает также привычные программные символы `*` и `/`. Если делитель равен нулю, выбрасывается `DivideByZeroException`. Если операция неизвестна, выбрасывается `ArgumentException`. Переполнение арифметики `decimal` приводит к `OverflowException`. Эти исключения перехватывает `CalculatorSession`.

`decimal` выбран для десятичных значений: например, `0,1 + 0,2` ведёт себя понятнее для калькулятора, чем при двоичном `double`. При этом `decimal` не имеет бесконечной точности: его диапазон и число значащих цифр ограничены, а бесконечные дроби при делении округляются.

## 8. Один расчёт по шагам

Пусть пользователь выбрал `×`, ввёл `2,5` и `4` и нажал кнопку:

1. `Form1` читает строки `"2,5"`, `"4"` и `"×"`.
2. `CalculatorSession.TryReadNumber` получает `2.5m` и `4m`.
3. `Calculator.Calculate(2.5m, 4m, "×")` возвращает `10m`.
4. `CalculatorSession` форматирует результат как строку `"10"`, оставляет `error` пустым и возвращает `true`.
5. `Form1` показывает `10` в поле результата.

Если вместо `4` указать `0` и выбрать `÷`, шаг 3 выбросит `DivideByZeroException`. Сессия превратит его в сообщение, вернёт `false`, а форма очистит поле результата и покажет «На ноль делить нельзя.».

## 9. Как устроены тесты

`Tests/SoftwareTesting.Tests.csproj` — отдельный проект MSTest. `Microsoft.NET.Test.Sdk` запускает проверки, `MSTest.TestAdapter` позволяет Visual Studio их обнаруживать, `MSTest.TestFramework` предоставляет атрибуты и `Assert`. `ProjectReference` связывает тесты с приложением. В файле тестов `[TestClass]` помечает класс, `[TestMethod]` — отдельную проверку, а `[TestInitialize]` задаёт русскую культуру перед каждым тестом для предсказуемого формата строк.

**Модульные тесты** вызывают только `Calculator.Calculate` и сравнивают числовой ответ через `Assert.AreEqual`. Ошибочные случаи проверяются через `Assert.ThrowsException`: тест проходит, только если возникло ожидаемое исключение.

**Интеграционные тесты** вызывают `CalculatorSession.TryCalculate`. Вспомогательный метод `Check` одновременно сравнивает признак успеха, текст результата и текст ошибки. Здесь проверяется граница между строковым вводом и арифметическим модулем.

**Системные тесты формы** создают `Form1`, показывают её через `Show()`, находят элементы по `Name`, заполняют поля и вызывают `PerformClick()` у кнопки. Затем читают текст результата или ошибки. `RunOnSta` запускает эти действия в STA-потоке: для Windows Forms это необходимо. Исключение из потока передаётся наружу, чтобы MSTest отметил проверку как неуспешную. Эти тесты проверяют события и состояние настоящей формы, но не заменяют ручную оценку внешнего вида на экране.

Всего 22 теста: 9 модульных, 8 интеграционных и 5 системных. В Visual Studio они доступны через **Тест → Обозреватель тестов**, а из терминала запускаются командой:

```powershell
dotnet test SoftwareTesting.sln
```

## 10. Как связаны тесты и исправления

Дополнительные тесты сначала фиксировались в отдельных коммитах и падали на соответствующей версии. Следующий коммит исправлял код. Для двух ошибок на каждом уровне в [отчёте](LAB1.md) приведены точные хеши коммитов, команды воспроизведения, ожидаемое и фактическое поведение.

Практический смысл такого порядка: падающий тест доказывает наличие проблемы, а успешный запуск после исправления защищает от её повторного появления. При изменении калькулятора можно снова запустить весь набор и убедиться, что прежние случаи продолжают работать.
