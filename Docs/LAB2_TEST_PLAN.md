## 1. Введение и объект тестирования

Калькулятор предназначен для выполнения четырёх арифметических операций над двумя десятичными числами в локальном Windows-приложении. Пользователь выбирает операцию, вводит числа и получает результат либо понятное сообщение об ошибке. Приложение подходит для учебной демонстрации модульного, интеграционного и системного тестирования.

В составе системы проверяются:

- `Calculator`: сложение, вычитание, умножение, деление и ошибки арифметики;
- `CalculatorSession`: преобразование текста в числа, вызов `Calculator`, форматирование ответа и ошибок;
- `Form1`: выбор операции, ввод, запуск расчёта, вывод, очистка и удаление устаревшего результата.

Вне области плана находятся тригонометрические функции, история вычислений, работа в сети, установка приложения через инсталлятор и проверка других операционных систем. Они отсутствуют в текущих требованиях к калькулятору.

### Функциональные требования и приоритет

| ID | Требование | Приоритет |
| --- | --- | --- |
| R1 | Четыре операции дают правильный ответ для допустимых чисел, включая отрицательные и дробные | Высокий |
| R2 | При делении на ноль приложение не показывает ложный результат и сообщает об ошибке | Высокий |
| R3 | Пустой, нечисловой ввод и переполнение обрабатываются без завершения приложения | Высокий |
| R4 | Принимаются дроби с `,` и `.`, а также записи `1,234.5` и `1.234,5` | Средний |
| R5 | Форма показывает актуальный результат или ошибку; после изменения данных старый результат исчезает | Высокий |
| R6 | «Очистить» возвращает форму в начальное состояние | Средний |
| R7 | Список операций ограничен поддерживаемыми значениями; результат нельзя редактировать вручную; Enter запускает расчёт | Средний |

## 2. Требования к тестам и перечень проверок

Для каждого сценария задаются входные данные, ожидаемый результат и уровень проверки. Тесты должны быть повторяемыми и не зависеть от порядка запуска. Строковые ответы проверяются при культуре `ru-RU`, поэтому десятичный разделитель в ожидаемом тексте — запятая. Для ошибок проверяется не только сообщение, но и отсутствие старого числового результата. После исправления дефекта запускается соответствующий тест и весь набор регрессии.

## 3. Стратегия тестирования

1. **Модульное тестирование:** запуск U01–U09 для чистой функции `Calculator.Calculate`; проверка обычных, отрицательных, дробных и ошибочных случаев.
2. **Интеграционное тестирование:** запуск I01–I08 для связки `CalculatorSession` → `Calculator`; проверка преобразования строки, передачи операции и возвращаемых сообщений.
3. **Системное тестирование:** запуск S01–S05 через настоящие элементы `Form1`; затем ручная проверка M01–M03 на рабочем столе Windows.
4. **Регрессия:** после изменения кода запуск всех 22 автоматических тестов. Для исправленного дефекта сначала запускается связанный сценарий, затем весь набор.

Автоматические тесты выполняются командой `dotnet test SoftwareTesting.sln` или из Обозревателя тестов Visual Studio. Для ручных сценариев приложение запускается командой `dotnet run --project SoftwareTesting.csproj`. Дефект записывается с версией кода, шагами, входными данными, ожидаемым и фактическим результатом, серьёзностью и состоянием исправления. Повторная проверка выполняется на коммите с исправлением.

### Критерии начала

- Проект собирается без ошибок на Windows с установленным .NET 8 Desktop Runtime.
- В решении доступны приложение и проект MSTest; зависимости тестового проекта восстановлены.
- Зафиксирована версия исходников, для которой выполняется прогон.
- Подготовлены входные данные и ожидаемые результаты из раздела 2.

### Критерии завершения и приостановки

Автоматическая часть считается завершённой при 22/22 успешных тестах, отсутствии открытых дефектов высокой серьёзности и сохранённом результате прогона. Полное системное завершение требует также M01–M03 без ошибок; до их проведения статус ручной части остаётся «не выполнено». Если сборка не проходит, окно не запускается или найден дефект, блокирующий дальнейшие проверки, прогон приостанавливается до исправления среды или кода; после исправления выполняется повторный запуск.
